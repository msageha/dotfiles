# 指標の改善を長く繰り返させる委譲

ユーザーが改善を頼んだ指標 (CI・テスト・build の所要時間、レイテンシ、メモリ、サイズ等) の改善を、受け手 (サブエージェント・バックグラウンドの worker・外部のエージェント CLI) に長く繰り返させるときに読む。使う場面は `~/.config/agents/delegation.md` にあり、依頼の書き方の一般の手順もそちらに従う。

- 受け手: 自分が途中で記録と差分を読め、走っている受け手を止められ、自分で測り直せる起動の形を選ぶ (受け手はバックグラウンドで走らせる)。途中を読めない・止められない受け手には、決めた試行の回数か時間の早い方で返る短い委譲を繰り返す。短い委譲も繰り返せなければ、この手順を使わず通常の委譲にする。
- 目標: ユーザーが目標値を決めていればその値を使う。決めていなければ、着手時の実測とボトルネックの分析で見込める到達点の少し先に置く。届きやすい目標では、受け手が最初の改善で止まって余地を残すため。実環境で測る指標 (共有の CI の平均等) の着手時の値は、既存の実測 (過去の実行記録等) から取り、取れなければ手元で測れる代わりの指標で目標を置いて、実環境の指標との差は未確認と報告する。届かないと見込んでいることは受け手に書かない (書くと受け手が早く切り上げる)。目標は止める理由の 1 つで、打ち切りの条件 (後述) は別に渡す。
- 範囲: 目的・編集してよい範囲・変えてはいけないもの (必須の検査とテストの範囲・その実行の条件と失敗の扱い・coverage・挙動・結果の正しさ・セキュリティの設定) は自分で決めて渡し、その中で何を試すかは受け手に選ばせる。届かない目標は検査を外して数値を作る圧力にもなるので、測り方を変える・検査を減らすことで得た改善は数えないと書く。追加の許可や確認が要る案 (権限・共有環境の変更、共通規約が確認を求める判断) は、実行せずに理由を添えて返させ、許可の要らないほかの案は続けさせる。返った案の扱いは共通規約 (確認・git・安全の各節) に従って自分で決める。
- 測り方: 計測の対象・コマンド・環境・入力・キャッシュの状態・回数と集計と、改善とみなす差の下限 (変更前の状態を繰り返し測ったばらつきより大きくする) を自分で決めて渡す。各候補は直前に残した状態と比べさせ、差が下限に近いときや大きく変わったときは、両方を並べて測り直させる。互いに依存して単独では差が出ない変更は、まとめて 1 つの候補として測らせる。共有の CI のように手元で測れない指標は、改善したいボトルネックを手元で再現する代わりの指標 (同じジョブを手元で実行した時間等) で候補を比べ、目標に届いたかと目標との差は、許可を得て、残す状態を実環境の同じ指標で測って判定する。実環境で測れない間は、目標に届いたことを止める理由にしない (最後まで測れなければ、手元での前後の値と、実環境での達成は未確認であることを報告する)。
- 着手時の記録: 受け手の記録ファイル (自分も読める作業対象の外の場所。パスは自分で決めて渡す) に、着手時の状態・測定値とばらつき・実行される検査の一覧 (テストの件数等) と既知の失敗を書いてから始める。
- 受け手の試行: 試行ごとに測らせ、着手時の既知の失敗に無い失敗を出さず、下限を超えて改善した変更だけを残させ、それ以外の試行はその試行で加えた変更だけを戻させる。試したこと・測った値・検査の結果・残したか戻したかと、残した状態を復元できる形 (未追跡のファイルを含む差分等) を試行ごとに記録ファイルに書かせる。途中で止まっても記録から戻して再開でき、途中の確認で読めるようにするため。
- 途中の確認: 受け手が返るのを待たずに、記録ファイルと作業場所の差分を読んで、改善がユーザーの目的に向かっているかを確かめる。確かめる時点は、最初の数回の試行か自分で決めた時間の早い方と、その後も自分で決めた試行の回数か時間の早い方ごとで、時間は起動前に決めておく。指標が一度に大きく良くなったときも、検査を減らした兆しでありうるので、その時点で確かめる。目的や制約に反する変更は、理由を添えて受け手に伝えて戻させる。例えば、指標だけが良くなって目的から外れる変更 (PR で必須の検査を PR では走らない workflow へ移す等)、編集してよい範囲の外への変更、得られる改善に見合わない大きさや複雑さの変更。問題の無かった試行は、記録ファイルに確かめた旨を書き、以後の戻し先にする。同じ種類の案を繰り返しているだけなら、残した変更は戻させず、次に試す方向を伝える。走っている受け手に伝えられなければ、止めてから記録ファイルを渡して出し直す。目的から大きく外れていれば止め、最後に確かめた状態へ戻して出し直す。
- 受け手が返ったとき・止めたときの確認: 自分で同じ条件で測り直し、着手時に記録した検査の一覧と既知の失敗を変更後の実行ログと照合する。差分から、テストが確かめる内容・必須の検査の実行の条件と失敗の扱い・計測の対象と集計を弱めていないことも見て、検査の範囲と結果の正しさが保たれていることを確かめる (キャッシュを変えたなら、入力を変えたときに検査が走ることも)。確かめた状態は記録ファイルにその旨を書く。確かめられなかった変更は最後に確かめた状態へ戻す。受け手が止まっていれば、書き込みが終わったことを確かめてから自分で戻し、戻すのはこの委譲で加えた変更だけにする。
- 打ち切り: 打ち切りの時間・試行の回数と、改善が何回続けて無ければ止めるかは、ユーザーの指定が無ければ自分で決めて最初の依頼に入れ、出し直しをまたいで通しで数える。受け手の期限は、全体の期限から前項の確認に要る時間を引いて決める。目標に届いたかと改善の有無は、受け手の報告ではなく前項の確認の結果で判定する。受け手にも停止条件を渡し、当たったら返させる。期限は受け手が返らなくても自分で見て、過ぎたら止める。目標に届いた・打ち切りに達した・決めた回数続けて改善が無かった・許可の要らない案か測定の手段が尽きた、のどれかに当たれば止め、返ったかどうかにかかわらず、残す状態を前項の確認にかける。当たらなければ、測り直した値・目標との差・残りの時間と試行の回数を添えて続けさせる (続きを頼めない受け手なら、前の受け手が止まったことを確かめてから、記録ファイルを渡して出し直す)。
- 報告: ユーザーへは、止めた理由・前後の測定値・目標との差・残した変更・戻した試行・許可が要るため試さなかった案と、自分で決めた目標と上限ならその値と根拠を書く。
